用户已授权在独立测试环境执行下面预算内的生成、修复并提交分支。已有 Draft PR 时更新该 PR，无需创建重复 PR。不合并、不部署或切换生产。

## 1. 环境与依赖准备

- 使用独立 worktree/checkout、全新测试数据目录、一个测试账号、并发 1、单 worker。本机监听，不影响正在运行的旧服务。
- Cookie 和服务 Key 由用户在测试管理页或明确指定的本地私密配置中提供。不要在报告、Git 或对话中打印凭据，也不要搜索无关账号数据。
- 缺少账号、Docker、网络或写权限时，继续其他可做阶段，最后集中列出阻塞点。
- 核对 `protocol-dependency/` 的固定源与补丁；通过真实 Git 提交准备依赖：
  ```bash
  python tools/prepare_protocol.py --clone
  python -m venv .venv
  .venv/bin/python -m pip install -r requirements.txt ./.protocol
  ```
  Windows 使用 `.venv\Scripts\python.exe`。已有协议 checkout 可使用 `--checkout`。不要用 mock archive / snapshot 代替真实 Git 源后宣称准备流程通过。
- 独立进程确认真实 `curl_cffi`、cryptography、协议包及 `protocol.json` 可用。服务进程不得注入测试替身或上一轮临时依赖目录。
- 记录实际安装的依赖版本。只有具体兼容问题需要时才调整依赖，不顺手升级整个项目。

## 3. 实号预算与可续跑记录

总上限：**6 次文本、2 次图片、1 次视频**。失败、超时、结果未知也占用预算。查询、恢复和下载原文件不产生新的生成调用。不得为凑齐通过项自动重发。

提交前建立简单的案例记录：case_id、发送意图与时间、请求摘要、账号匿名标识、预算、请求/operation/task/session/node ID、状态和证据路径。先记录发送意图再 POST。中途退出后不能证明未发送时，只查原操作或标待确认，不重新跑整套生成。

现成 smoke 的 `--generate` 包含 1 文本+1 图片，`--generate --video` 包含 1 文本+1 图片+1 视频，每轮图片幂等键不同。不要先跑前者再跑后者。可以补一个轻量的逐项执行入口，不需要引入大型测试框架。

| 案例 | 预算 | 必须验证 |
| --- | --- | --- |
| T1 Chat 非流式 | 文本 1 | 原接口、有效 assistant 内容、正确结束字段 |
| T2 Chat SSE | 文本 1 | 实际事件与增量拼接；正常成功才发正常完成 |
| T3 Responses 非流式 | 文本 1 | 原响应契约与输出 |
| T4 Responses SSE | 文本 1 | 实际增量、事件顺序与终结事件 |
| T5 取消/重启/恢复 | 文本 1 | 确认已提交且仍执行时断开客户端，检查租约释放、unknown/隔离与磁盘记录；重启后查询原会话，不重发 |
| T6 浏览器回退 | 文本 1 | 隔离环境切换后完成一次真实文本，证明回退通信可用 |
| I1 异步图片 | 图片 1 | 原创建/查询接口与媒体 URL；完整图像解码，记录格式/尺寸/字节数/哈希 |
| I2 双参考图编辑 | 图片 1 | 两张顺序可区分的小测试图通过原编辑接口上传；结果完整解码 |
| V1 短视频 | 视频 1 | 原任务流程；ffprobe 检查视频流/时长/尺寸；ffmpeg 完整解码至空输出，记录字节数与哈希 |

T5 若断开时任务已完成，则该次没有触发未知状态，不能伪称实号取消恢复通过，也不能自动增加第 7 次文本。使用可控测试补充并标明实号场景未观察。

I1 可以在媒体交付时做一次测试专用的受控失败，再恢复原文件；不得重复生成。图片文件头或 HTTP 200 不代表完整图像。视频只探测首帧也不足以证明完整可用。

同步图片生成、b64_json 等未分配实号预算的格式组合用可控接口测试验证，并明确未做对应实号验证。额度不足、模型拒绝、上游异常和实现错误分别归类。

## 4. 异常与恢复

优先用测试专用 HTTP/WebSocket 对端或受控传输边界复现故障；保留真实原生 I/O 的测试与只用合成 peer 的测试分开记录。真实账号只复用上面的调用。

必须核对：

1. 发送前失败不会触发服务端自动换号或重发。
2. 已提交后断连/超时只保留一次上游生成提交；未完成 activity 的部分文本不能返回成功。
3. 客户端断开后，generator、队列和租约有界清理；unknown 对应账号仍保持隔离。
4. 重启后操作记录仍在，恢复绑定原账号/session/node/VM，不因内存清空而自动重新生成。
5. `delivery_failed` 恢复只下载原媒体；可以用调用边界计数和文件哈希证明。
6. 账号或 VM 身份不匹配时保留待确认或明确拒绝，不串到其他账号。
7. 人工导入新 Cookie 后，旧会话写回不能覆盖。覆盖 expiry、删除与重复 Set-Cookie 顺序。
8. 401、403、临时网络错误按现有健康契约处理；用受控响应验证，不故意损坏真实账号。
9. 放弃恢复返回 `upstream_cancelled:false`，不能宣称取消上游任务。
10. 下载限额、接收超时与流队列有界；半成品不公开为完整媒体；错误 SSE 不伪装成功。

通过真实 Muse 或本地受控 HTTP/WebSocket 对端提供至少一项真实 `curl_cffi` I/O 证据。不能以替身 import 成功证明原生传输可用。记录生成调用次数和原会话关联，不以一行“没有重发”的日志代替证据。

## 5. 生命周期和回退

- **Cookie 轮换**：观察真实上游变化，记录匿名指纹/凭据版本；证明 Store 写回和重启后的认证。未发生真实轮换记 NOT_OBSERVED。合成 Set-Cookie 测试单独标注。
- **VM 唤醒**：先检查保活和预热。候选 SDK 有 idle_sleep 不代表当前嵌入层运行其 AccountPool 定时器。只有观察到实际休眠/失活和恢复才记通过；等待若干分钟或重启本地进程不能替代。可把尚未执行的 T1–T4 安排在观察到唤醒之后，不增加调用。
- **连接/资源**：记录活跃账号的连接复用、并发限制、空闲和任务后的内存摘要；不凭少量样本宣称性能提升百分比。历史重连累计数与同时连接数分开。
- **多账号/代理**：合成隔离测试必须覆盖。无第二个实号时，不宣称多账号真实通过；目标部署确实需要时另列上线前待验项，不扩大本轮预算。
- **回退**：先停止测试实例并处理/保留 unknown，构建带 Chromium 的镜像：
  ```bash
  MUSE_INCLUDE_BROWSER=1 MUSE_BACKEND=browser docker compose --env-file .env up --build -d
  ```
  PowerShell 先设置对应环境变量。验证测试账号、任务和媒体记录仍可读取，并执行 T6。缺浏览器或有效会话时标 BLOCKED。不得让两实例同时占用同一账号。
- 不用未经集成的旧源码覆盖含未知任务的新数据。不在本任务中迁移或切换生产。

## 7. 判定

每项同时注明证据层级（合成对端 / 原生网络库 / 真实 Muse）与状态：

- PASS：在声明层级实际执行并满足判据。
- FAIL：实际观察到违反契约，给出复现。
- BLOCKED：缺账号、额度、网络、依赖或权限等条件。
- NOT_OBSERVED：真实轮换、休眠等事件未发生。
- NOT_RUN：未执行或不在本轮范围，不能算通过。

整体结论分级：

1. **构建与离线验收通过**：仅证明可构建、可启动及相应回归。
2. **可进入单账号试运行**：原生部署、预算内主要真实接口/媒体与关键异常受控测试通过，清楚披露恢复和生命周期覆盖。核心路径有 FAIL 时不能给出此结论。
3. **达到本次现网替换验收门槛**：真实 unknown/重启恢复、Cookie 轮换、VM 唤醒、浏览器回退及目标部署所需代理/多账号条件均有证据。仍只提交结果，不自动切现网。

最终回答应直接说明：本次证明了什么、哪里失败或阻塞、是否可试运行、现网替换还差什么，以及最少需要用户补充什么。
